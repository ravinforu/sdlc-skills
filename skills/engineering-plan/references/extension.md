# Native Spec Kit extension

Use Spec Kit 1.2.0 or later within major version 1. The extension was validated against 1.2.0; verify hooks again after upgrades. The standalone source repository has extension.yml at its root, commands/, guide/, docs/, scripts/install.py, scripts/package.py and tests/. Its checked-in guide is complete and can be maintained without a personal skill or external export step. Use its README.md as the entry point.

When working on this personal authoring skill, the extension assets live in assets/speckit-extension. The authoring skill's scripts/build_extension.py exports them plus this skill and references into a new speckit-engineering-plan source folder and Engineering-Plan-SpecKit-Repository.zip. This authoring-only exporter is not needed by consumers or maintainers of the exported repository.

The package's docs/install.md owns installation and migration instructions. Keep the source checkout separate from applications. Run `python3 scripts/install.py --repo /path/to/application` from the source checkout, or run `specify extension add /path/to/speckit-engineering-plan --dev` in an initialized target. This copies the extension into .specify/extensions/engineering-plan and registers commands for installed integrations. Each target owns its constitution, hook configuration and feature outputs. Updates to the shared source do not automatically update target installations. Keep using the core constitution, specify, clarify, plan, tasks and implement commands. Twelve mandatory hooks invoke eleven namespaced commands (specify and clarify share spec-check).

Before hooks prepare stage-specific guidance without changing the feature. After hooks reconcile constitution, specification, design, tasks or implementation evidence. They never call core commands recursively. The design hook owns detailed architecture/security completion after planning. Feature artifacts remain in the resolved Spec Kit feature directory: spec.md, plan.md and tasks.md remain the entry points.

This extension does not replace core templates, require an API key, launch a background agent, or run a CI gate. It uses the active coding agent session. Mandatory means optional: false in Spec Kit’s hook configuration; actual execution still depends on the coding agent and current generated core commands. Verify the transcript and artifacts on a sample feature. Keep Engineering Review’s CI gate separate.

When migrating, remove only the older engineering-plan preset with the supported preset remove command. Run the extension’s configure command to update its managed constitution/agent guidance without replacing unrelated text. Do not delete existing feature documents or other extensions. Spec Kit preserves user-modified generated commands in some update paths; review any conflicts before claiming all stages are wired.

The separately distributed skill ZIP contains the planning guide and references, not the personal authoring exporter or legacy preset. Use the extension repository ZIP for Spec Kit installation and maintenance. Both distributions share the same API guidance.
